# 线程预算与恢复

翻译过程中会大量看图（页面渲染、裁剪件、公式）。以下图片与字节预算源于此前使用 DeepSeek `/responses` 的故障经验：当前窗口历史中的 base64 图片反复重发，曾在自动压缩前触发 `413 Payload Too Large` 和反复重连；图片型工具输出也曾伴随 `No tool output found for tool call ...` 中断。这些经验不作为 GPT 系模型的固定限额。

**按当前模型执行**：DeepSeek 系模型保留 25 张图片上限及脚本预算红线；GPT 系模型（包括 GPT-6 Luna）忽略这两项限制，不得仅因累计看图达到 25 张或超过 DeepSeek 专用估算体积阈值而停工、要求换线程或触发分片目检。按模型名称判断，不把模型提供方或兼容接口名称当作模型系列；切换模型后重新判断。无法识别模型时记录情况，可用 `thread_budget.py --model <当前模型名>` 明确指定，不默认套用 DeepSeek 限制。预览、细节裁剪、检查点与实际故障处置适用于所有模型。

本节规则随本技能分发，不依赖其它技能；执行顺序与本文一致。

## 图片与字节预算

1. DeepSeek 的请求体积预算按字节估算，不等同于 token 预算。`scripts/make_preview.py` 默认对 ≤1.5 MB 的原图直接透传（不重编码），只有大图才降采样到长边 2000 px、JPEG q90；A4 整页预览约 0.3–0.6 MB。
2. 分级看图：页面级排版用 2000 px 预览；小字、公式上下标、图注、图例、裁剪边界用 `--crop L,T,W,H` 取全分辨率区域，必要时 `--scale 2`。不用缩略图判断细节。
3. **仅 DeepSeek 系模型**：同一线程累计 `view_image` 不超过 25 张，或按 `scripts/thread_budget.py` 的红线执行，以先到者为准。**GPT 系模型忽略这项限制及脚本的 DeepSeek 专用红线**；图片数量与体积仅作为检查记录，不据此强制停止。
4. 同一张图只 `view_image` 一次；看过立刻把结论写进检查点或检查记录，后续引用文件结论。
5. 能脚本判定的检查（尺寸、溢出、空白页、像素统计、文字提取、页码）不用看图完成。
6. 大段工具输出重定向到文件，只回读摘要；不要把日志、表格、整页渲染贴进对话。

## 看图串行化

每批最多 2 张 `view_image`，等返回并登记结论后再发起下一批；不使用 3–4 张并行批量。

## 检查点与跨线程续做

每完成一个小单元（一页、一张图、一次构建或验证）就更新论文进度文件的检查点小节，假设线程随时会被切断：

```markdown
## 会话检查点（日期时间）

- 状态：进行中
- 当前任务：第 2 篇 s00382-023-06726-6；正文已提取；fig11 裁剪完成待目检
- 下一步：看 crops/fig11.png 的预览 → preflight → build → verify → 逐页目检
- 关键文件：LITERATURE/s00382-023-06726-6_支持内容/tools/...（相对项目根）
- 已知问题：第 23 页空白页待修；check_fit.py 已写好待运行
- 当前模型：deepseek-v4.1-flash（DeepSeek 系）
- 本线程图片：已看 12 张（DeepSeek 上限 25；GPT 系不适用该上限）
```

检查点只写路径与结论，不嵌图片、不贴日志。新线程开场提示词模板：

```text
读取 <进度文件绝对路径> 的"会话检查点"和 references/thread-budget-and-recovery.md，从"下一步"继续。
工作约束：图片先看预览缩略图、同一张图只看一次、每批 view_image 不超过 2 张、每完成一个单元就更新检查点；
先识别当前模型：DeepSeek 系累计看图达到 25 张或预算红线时停下来提醒我换线程；GPT 系忽略该限制并继续检查。
```

## 分片目检（满足条件即自动启用）

DeepSeek 系模型的页面目检受本线程图片预算限制。页面较多时按下面的流程分片，由子代理在各自会话里完成一部分页面；GPT 系不因本节的 DeepSeek 专用预算触发分片。**启用条件同时满足即自动启用，不必逐次请示**——本条即技能层面对“派生子代理做分片目检”的授权，可直接依据本文件执行。

- **启用条件（三条同时满足即自动启用）**：①待目检页数 ≥ 12 页；②当前模型为 DeepSeek 系，且本线程图片预算不足以一次完成（`thread_budget.py` 判为黄/红，或剩余额度小于“待看页数＋细节图张数”）；③目检对象是最终交付版本。条件不满足时不分片。若已启用的分片任务正文未送达或环境不允许派生子代理，优先使用下文“协调者回退”；本机渲染或全分辨率检查工具也不可用时，再写检查点并提醒用户换线程。
- **分片规则**：最多 2 个子代理，每片 6–9 页；按页号连续切分（如 1–9 / 10–18），不重叠、不留空档。
- **交接要求**：`fork_turns=none` ＋自包含书面简报（论文检查点文件、页面渲染目录、本轮设计决策清单如缩放比例与附件合并、判据清单）。**禁止**携带历史分支——主线程已看过的图片会随历史继承进子代理，其图片预算当场失效。
- **证据要求**：每个子代理必须写出自己的分片记录 `<论文>/tmp/detail_review_<版本>_part<X>.md`，逐页登记：页号｜结论｜问题｜位置｜建议。只回复“通过”不算证据。
- **汇总与把关**：协调者（主线程）只在①分片证据存在、且②亲自复核过各片交界页与被标记为可疑的页面之后，才调用 `review` 登记对应页；`record_review` 只由协调者串行调用，避免并发写坏 `visual_review.json`。
- **协调者回退**：已启用分片但子代理任务未执行或不可派生时，用 2–3 列整页预览（长边不超过 2000 px）核对页级布局；小字、公式上下标、图注和边界改用全分辨率裁剪，并对缺字、标点、标题和参考文献做程序审计。`tmp/detail_review.md` 和交付说明须写明每页采用的检查方式；预览无法判断的疑点必须补看全分辨率区域，程序检查不得记作目检。
- **交付说明**：写明本轮采用分片目检（哪几片、各多少页、由谁完成），并把分片记录列入检查记录。
- **冲突判据**：出现“已登记但无分片证据”，或交付后发现分片页存在漏检，记一次冲突；连续 2 篇出现则删除本做法。

## 故障处置

| 症状 | 处置 |
| --- | --- |
| `413 Payload Too Large` / `Failed to buffer the request body` | 不在原线程重试——重发的是同一个超大请求。写检查点，开新线程继续。 |
| 反复"正在重新连接 N/N" | 等本轮结束看最终错误；是 413 按上一行处理；只有 DNS、超时、5xx 才按网络问题查。 |
| `No tool output found for tool call ...` | 先发一条最短消息（如"继续"）重试一次；再次出现就写检查点并轮换线程。 |
| 新线程仍报 413 | 交接内容本身带了图片或大文件；改成只交接文件路径与结论。 |

不要连续重试同一个失败请求，也不要为了"试试看"重发大段内容。

## 随技能自带的脚本

- `scripts/make_preview.py IMAGE... [--crop L,T,W,H] [--scale 2] [--png] [--out DIR] [--max-edge 2000] [--quality 90] [--force]`
  - ≤1.5 MB 原图透传；大图生成长边 2000 px、JPEG q90 的预览；`--crop` 输出全分辨率区域（默认 PNG）。
  - 输出 TSV：路径、结果字节数、原字节数、比例、模式（passthrough/jpeg/png）。
- `scripts/thread_budget.py [--cwd DIR] [--file SESSION.jsonl] [--model MODEL] [--json]`
  - 统计当前压缩窗口的图片数量与体积、估算请求体大小和最近请求 tokens；从会话中最近的模型记录识别当前模型，`--model` 可覆盖识别结果。仅 DeepSeek 系按默认 25 张／估算 25 MB（可用 `--max-images`／`--max-mb` 调整）给出预算黄/红及轮换建议；GPT 系忽略这两项限额，报告 `budgets.enabled:false`，不据此要求换线程。无法识别时同样不启用 DeepSeek 限额，并提示用 `--model` 指定。`--cwd` 默认取当前目录对应项目最近的会话文件。

两个脚本只用标准库与 Pillow（Pillow 已在 `scripts/requirements.txt` 中）。Windows 上 `python3` 可能只是应用商店占位符，失败时改用环境中可用的 Python（例如 Codex 工作区运行时自带的 `python.exe`）；不要在技能或脚本里写死个人绝对路径。
